# Source and Evidence Dictionary

This document explains what each public layer means. It is an information-architecture guide, not a new mathematical theorem.

| Layer | Location | What it may establish | What it may not be silently promoted to |
|---|---|---|---|
| Audited release | `paper/audited-release/` | claims explicitly marked audited/proved/certified in that release | a proof of any downstream open node |
| Lean/formal bank | `RequestProject/` | finite/algebraic theorems checked at their literal hypotheses | missing analytic estimates, contour theorems, or certificate existence |
| Finite certificate | release `certificates/` plus replay scripts | exact/outward-rounded numerical statements recorded by the certificate | an unencoded physical theorem |
| Live candidate | `frontier/YYYY-MM-DD-name/` | research hypotheses, reductions, candidate closures | audited baseline or certified capacity |
| Corrections | `CORRECTIONS_AND_RETRACTIONS.md` | explicit retirement/supersession rules | deletion of the historical source |
| Archive | `archive/` | provenance and research archaeology | current authority merely because a file is newer-looking or has a large revision number |

## Current authoritative source order

For the 5 September 2026 state:

1. R12 audited status/capacity ledger;
2. R12 source-provenance and formal-scope documents;
3. exact Lean/finite evidence at its literal scope;
4. live static-Ramanujan candidate frontier;
5. historical safe banks and public-review manuscripts.

If two sources disagree, do not merge them silently. The audited baseline controls until a later audited release explicitly supersedes it.

## Physical versus abstract statements

A recurring firewall in this programme is the distinction between an abstract correct theorem and a physical source instantiation. Every public claim should therefore identify whether it is:

- abstract finite/algebraic;
- source-specific and physically instantiated;
- conditional on an analytic input;
- numerically certified;
- or merely a candidate route.

See the R12 `FORMAL_MODULE_MAP.md` for the current theorem-to-Lean mapping.
